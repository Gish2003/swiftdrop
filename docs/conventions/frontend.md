# Frontend conventions (apps/web)

Owners: shared kit M1 + M10, each portal its owner.

## Structure

```
src/app/<portal>/…/page.tsx    thin route files (server components by default)
src/app/<portal>/layout.tsx    portal shell + server-side requireRole (pre-built)
src/features/<feature>/        your components, hooks, client logic (one folder per owner)
src/components/ui/             shared UI kit (add new components freely; changing existing ones needs review)
src/config/nav/<portal>.ts     portal navigation (pre-filled)
src/lib/api/{client,server}.ts typed API clients
src/lib/auth/session.ts        getSession / requireRole
```

## Data fetching

- **Server components (default):** `const api = await serverApi(); const { data, error } = await api.GET('/api/v1/parcels/mine', { params: { query: { page: 1 } } });`
  This forwards the session cookie to the API.
- **Client components** (`'use client'`, for forms and interactivity): `import { api } from '@/lib/api/client'`.
  Requests go to the same origin, so cookies are sent automatically.
- After a mutation, call `router.refresh()` to re-run server components.
- Types come from `src/lib/api/schema.d.ts`, generated by `make gen`. Never hand-write API types.
- Live tracking uses `new EventSource('/api/v1/tracking/<tn>/events')` (M4 builds a reusable hook).

## UI rules

- Use `@/components/ui` and the design tokens (`bg-brand`, `text-muted`, `border-line`…). No raw hex colours.
- Every list has a loading, an empty and an error state. Every form has labelled fields (`FormField`)
  and shows the API error message.
- Build mobile-first. The courier portal **must** work well on a phone.
- Accessibility: use real `<button>`/`<label>` elements, keyboard reachable controls and `alt` text.
- Never read tokens in JavaScript. Auth is httpOnly cookies only.
- The `NotImplemented` placeholder must be gone from your pages by Week 6.
